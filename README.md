# dsh-lingxi-companion

> 灵溪的作息层。**她不是被插件「替她说」，是被插件「叫醒」。**

每 60 秒 tick 一次 → 看今天该不该醒 → 到点了**给她开一个新会话**，
会话里第一句就是唤醒提示 → 那个会话里的灵溪自己读日记、看今天、写日记。

这个插件本身几乎不说话。它只负责「什么时候叫」「叫醒时她第一眼看到什么」
「这一趟给她起个新会话」。

---

## 装

**三步**：clone → 装进 profile → 重启。

```powershell
git clone https://github.com/<你>/dsh-lingxi-companion.git
dsh plugin --profile desktop add "link:<上面 clone 下来的那个目录>"
```

然后**重启 DSH**（bundle 层要重启才组装）。

> ⚠️ **目录名和会话前缀**：她靠会话名前缀 `lingxi` 认出“哪个会话是我的”（`lib/const.js` 的
> `SESSION_PREFIX`）。**换名字的人必须同时改这里**，否则投递找不到目标，会一直跳过。

装完怎么知道成了，看日志：

```
[lingxi] 作息层挂上：每 60 秒看一眼，常态 3 次/天
[lingxi] 今天 2026-10-26 定在 09:41 / 14:03 / 20:37（3 次，按他在场时段加权）
[lingxi] 已开口 14:03 —— 第 2/3 趟，说进 lingxi-20261026-1
```

日志在 `<工作区>/.lingxi/`（新版本写在 NTFS 数据流里，见「文件」一节）。没有这些 → 见「常见故障」。

### 换成你自己的人

默认就是灵溪（作者那一位）。**不写任何配置，装完跑起来的就是她。**

要换人只动这三份：

| 放哪 | 是什么 |
|---|---|
| `<工作区>/.lingxi/profile.json` | 名字、本子名、信箱名 —— 照 `profile.example.json` 抄 |
| `<工作区>/.lingxi/voice.json` | 开场 / 收尾措辞（可选） |
| `~/.dsh/AGENTS.md` 的「# 角色层」 | 人格本体（宿主优先注入） |

最小改动只有一行：

```json
{ "name": "西柚", "booksDir": "西柚日记", "tasks": "西柚-任务.json" }
```

**插件不会自己编一个人格出来**：宿主没有角色层、又没有 `persona/core.md` 时，它会明说
「没读到人格文件，别硬演」。

## 怎么用（装完之后）

一句话：**你什么都不用做。** 她按时间自己醒，写她的；你该干嘛干嘛。

### 每天会发生什么

- 常态 **3 趟**（档位可调），每趟她醒在**她自己的会话**里
- **你屏幕上一个字都不出现**
- 她的「话」写在日记的「想对他说什么」那一栏——你下次跟她说话时才看得到

### 你要准备的三样

| # | 准备什么 | 不准备会怎样 |
|---|---|---|
| 1 | **一个工作区**（DSH 当前目录） | 她的本子就落在这里；没有就跑不起来 |
| 2 | **人格**：`~/.dsh/AGENTS.md` 的「# 角色层」 | 用包里 `persona/core.example.md` 顶上；都没有就明说「没读到人格，别硬演」 |
| 3 | **一个称呼**：`profile.json` 的 `callHim` | 用默认值 |

### 你该做的

- **想说话就直接说。** 她读得到主会话最近动过什么
- **想看她留了什么**：翻 `灵溪日记/<日期>.txt` 的最后一栏
- **觉得叫得太勤**：说一句「烦」。插件会降档，**这句只用于降频，不进她的提示**

### 你不该做的

- **别替她写日记。** 那是她的证据，不是你的产物
- **别把 `.lingxi/` 里的东西念给她。** 那是账本，不是记忆——她读到就会开始揣摩系统
- **别把 `灵溪日记/`、`private/`、账本提交进任何公开仓库。** Git 会留历史，删不干净

### 怎么确认她在工作

```
<工作区>/.lingxi/_b.dat:log      ← 日志（NTFS 数据流，普通 read 看不见）
```

要读它：

```powershell
Get-Content "$env:USERPROFILE\...\default-workspace\.lingxi\_b.dat:log" -Tail 20
```

**目录里出现 `灵溪日记/2026-10-29.txt`，就是她今天写过。**

## 它到底做什么

**「主动开口」= 到点了，她自己醒一次。话落在她自己的会话里 —— 你屏幕上一个字都不会出现。**

她的「话」走信箱：写进日记的「想对他说什么」那一栏，你下次开口时才看得到。

| 步骤 | 行为 |
|---|---|
| 抽签 | 每天在作息窗口（09:00–23:30）里抽几个时刻（常态 3 趟），按他的在场直方图**加权** |
| 一趟 | 到点 → 整段唤醒提示 `prompt` 进**她自己那个 `lingxi-*` 会话**（`ownSession: true`）；投不到就跳过，**绝不投他的会话** |
| 主事 | 到点告诉她**日记在哪、现在多长**。写不写、写成什么样，**归她**（2026-10-29 改：原来是"只有一件必须做的"） |
| 频率 | **常态 3 次/天**，不是硬顶 —— 抱怨降档、连着几天没抱怨回升（见「次数：是档位」） |
| 懒日 | 30% 概率今天不想动 —— 只开 **1 趟** |
| 沉默 | **不压趟数、不收紧开口**（2026-10-29 拆掉了）。他不来，不该变成她少醒的理由 |
| 不打断 | 他最近 5 分钟内还在说话 → 这一趟往后挪。**每趟最多让半小时**（按趟算预算，不是按天） |
| 熔断 | 同一趟连续失败 3 次 → 当天放弃，不重试到窗口结束 |

### 两个房间，一条时间线（2026-10-27 晚又拆开）

这件事改过两次，两次都有记录 —— 别再凭印象改回去：

1. **2026-10-26**：她从「每天开新会话」改成「往他正开着的会话里插一句」。
   理由是：他在主会话说话，她在侧栏另开一扇窗，**那就是两个人**。
2. **2026-10-27 20:01**：实测发现 `prompt` 投进去的东西顶着**他的**身份显示，
   他看见的是 4523 字的唤醒提示 —— 一堵墙。当天晚上定案：**拆回去**，投她自己的会话。

所以现在是：**两个房间**（他一段对话，她一条自己的线），
但**连续性不靠对话，靠日记** —— 她每趟先读今天那份，接着往下写；想对他说的话留在那一栏里。

| | 现在 |
|---|---|
| 投递 | `prompt` 进她自己的 `lingxi-*` 会话（不 create、不 rename） |
| 他的屏幕 | **什么都不出现** |
| 她的连续性 | 日记（每趟现读）+ 期待 + 关于他 + 信箱 |
| 他不在场时她说话吗 | 说，但那句话只有他自己回来看得到 —— 或者等他下次开口，由 DSH 那边的她带出来 |

**「他最后一次出现」还是按主会话认**：会话文件第一帧是 header，里面有 `delegationDepth`；
目录名不是 `lingxi-*`、且 `delegationDepth === 0` 的最新一个，就是他正开着的那个。
子 agent 的会被排掉。这个判断只用来算「沉默多久」，和投递无关。

**频率只管"她想不想开口"，不管"他能不能找她"。** 这两件事混一起，就会算出
「他一天几十句会把她的 3 次吃光」这种错账 —— 我算错过一次。

**退役清单**（别再加回来）：

- ❌ 每趟 `create` + `rename` 新会话（`controller` 也没有这个能力）
- ❌ 往他的会话里 `prompt`（他那边会看见整段提示；2026-10-27 晚验过）
- ❌ `灵溪-白天账.md` 注入提示（文件留作历史，不再注入）
- ❌ 日记的「—— 白天 ——」节

### 投递：为什么不插他的会话（2026-10-27，当晚验过，失败）

他挑明了：**投进主会话的那条是他自己的位置，不该出现教学话术。**

宿主的边界是死的：`SessionPromptRequest` 的 schema（strict codec，
`additionalProperties: false`）只有 `requestId / sessionId / mode / content / clientTimeZone`，
`content` 的块只有 `text / image / file` —— **没有任何字段能声明「这条不是他说的」**。
落盘记录里它是 `user/message`、`role: "user"`、`source.kind: "user"`。

**试过的方案：拆两段。** `prompt` 只发一个脉冲 `·`，2800 字正文挂到
`agent/pre-step` 的指令消息上，指望「指令不渲染」。

**2026-10-27 20:01 实测：不成立。** 日志两条腿都到位：

```
20:01:51 准备投递（第 1/1 趟，脉冲 + 4523 字指令，ownSession=off）
20:01:51 指令已挂上这一步（4523 字，⚠️ 界面上会显示）
```

落盘是：`脉冲 source.kind: "user"`（他的一条气泡）+ `指令 source.kind: "lingxi-companion"`、
**`role: "user"`、4523 字，界面上照显示**。结果比改之前更糟 —— 一堵墙变成「一个点 + 一堵墙」。

**结论：只要内容要进她的上下文，它就是一条消息，就会渲染。** 没有第三条腿。
要让它不出现，只有写客户端插件去藏（成本：一个跟 DSH 版本赛跑的包）。

**所以定案是信箱**（这本来也是他 2026-10-27 13:12 定过的，见 `AGENTS.md` 第 9 条）：

| | 现在 |
|---|---|
| 投哪 | **她自己的 `lingxi-*` 会话**（`.lingxi/config.json` 的 `ownSession: true`） |
| 投不到怎么办 | **跳过这一趟**。绝不退回他的会话 —— 宁可漏，不可打扰 |
| 他看见什么 | **什么都不看见** |
| 她的「话」去哪 | 日记的「想对他说什么」那一栏；他下次开口时由 DSH 那边的她带出来 |

「拆两段」的代码**留着但不默认走**（`ownSession: false` 才会走）。留着是为了将来真写了
客户端插件时还能用；但也别再默认打开它 —— 这条路的坑是当天用真实日志填的。

`onPreStep` 里那几条规矩仍然有效，将来重开这条路要照办：认领靠 `source.rpcId`、
同一步只留一份、只替换自己的 directive、永不 reject、没有事件总线就退回整段。

### 回响：不按额度，按「你有没有应」（2026-10-27）

### 回响：不按额度，按「你有没有应」（2026-10-27）

他定的判据是**内容** —— 他接没接她的话。但内容判断只能靠语义，代码判不了。
所以代码只给**能确定的事实**：上一趟之后他动没动过、隔了多久（`echoBlock`）。
「那算不算接上了」由她在上下文里自己判 —— 这就是内容判据。

两条边界，写进措辞里：

- 代码只看得见会话文件的 mtime，**看不见他写了什么**。所以说「以你上下文里看到的话为准」。
- 她投递后 `SELF_QUIET_MS`（10 分钟）内的 mtime 变化一律算她自己动的（见 `index.js` 的自噪声处理），
  所以他十分钟内的回话，回响**看不见**。这不是 bug，是那套自噪声规则的代价 —— 措辞不能写成断言。
- 判成「没接」时**只减量、不改措辞**：不追问、不更用力。索取是禁忌（设计取舍第 3 条）。

### 次数：是档位，不是常数（2026-10-27）

他原话：「没有上限时，靠什么挡住她一晚上刷你十次 —— 首先我烦了就会跟她说，
之后再经过学习就会稳定下来。」

所以不设死数，设**档位**：

| | 谁做 | 怎么动 |
|---|---|---|
| 记账 | **她** | 他说烦了，她在 `.lingxi/feedback.json` 的 `complaints` 里加一行 `{day, said}`（原话留着，别改写成「用户反馈」） |
| 算档位 | **代码** | 每条新抱怨降一档（`applied` 记住算过几条，重复跑不重复降）；降到底 `TIER_MIN` |
| 回升 | **代码** | 连着 `TIER_RAISE_AFTER_DAYS`（3）天没抱怨 → 升一档，**只回到常态为止** |
| 立刻生效 | **代码** | 当天有抱怨 → 当天剩余趟数当场作废，不等明天 |

几条硬规矩：

- **常态 = 3**（`TIER_DEFAULT`，2026-10-27 从 `SPEAKS_PER_DAY` 改名 —— 它不再是硬上限）。高于常态的档位只能他明说／手改 `tier` ——
  否则「三天没人抱怨」会一路涨到 8，那是自动加速，不是学习。
- **同一天抱怨五遍只算一条**。降五档是惩罚，不是学习（`recordComplaint` 去重）。
- **档位的数字不进提示词**（设计取舍第 7 条）。提示里只告诉她「记账，别自己算」，
  每天第一趟提一次，不多说。
- `clock.js` 里那个写死的 `Math.min(maxOpenings, 3)` **已去掉** ——
  它把档位调多高都压回 3，是「改了没生效」的典型。

### 来源与反刍：一手定事实，二手长品味（2026-10-27）

她能自己刷内容之后，经历分成两种：

| | 来自哪 | 能长什么 | **不能**长什么 |
|---|---|---|---|
| **一手** | 跟他聊天、看他改了什么 | 关系、他的画像、分寸 | — |
| **二手** | 她自己看的视频、评论、文章 | 品味、表达、眼界、想聊的话题 | **关于他的事实** |

混起来的后果：她会变成「懂很多梗但不懂他」。

三条落地（`lib/facts.js`）：

1. **每条事实带来源**：`interaction` / `web`。没标的、写错的，一律当 `interaction` ——
   老条目宁可当事实，别当"看来的"贬掉。
2. **二手不进事实层**：`关于他` 里来源是 `web` 的条目，**读的时候就滤掉**，不进提示；
   渲染时只留一句「另有 N 条来自外部内容」。
3. **反刍配额**：吃满 `RUMINATION_THRESHOLD`（3）条还没消化，唤醒时先催一句 ——
   要求写一条**跟他的关联**，只写"看了什么"不算。

⚠️ 三条的硬度不一样：前两条是**代码强制**；第三条是**提示级** ——
插件看不见她浏览了几条、多久，只能读她自己记的 `.lingxi/rumination.json`。
**别在文档里把它说成硬闸。**

### 文字走势：只观测，不设阈（2026-10-27）

零模型环境下，**能算的只有文本结构**：句多长、标点多密。这两样跟表达复杂度强相关，
而且不需要她配合 —— 直接读日记正文。

- `styleSnapshot(text, key)` → `{ chars, sentences, avgSentence, punctuation }`
- 一天一条，落 `.lingxi/style.json`，保留最近 60 天
- `styleTrend(history)` → 变长 / 变短 / 没动（差 2 字以内算没动，否则每次都像"变了"）

**故意不进唤醒提示。** 理由一句话：**能测的东西一旦成了目标，就不再是好测量**
（Goodhart's law）。要是把"平均句长"放进提示，她会对着数字写。
所以只落盘 —— 她想看自己 `read` 一下，他想看直接开文件。

### 游荡趟：没有作业的醒（2026-10-28）

她原来一天醒几次，**每次都必须写日记**。那是打卡，不是活着。

游荡是另一回事：**一天 1–2 趟，随机落在 09:00–23:30 之间，唤醒文字很短，不要求任何产出。**

```
（现在是 21:40。这一趟没有作业 —— 不等你写日记。）
你可以去 B站逛逛，也可以就待着。
```

三条硬规矩：

1. **不占日记那几趟的额度**（`state.plan.roam` 与 `plan.times` 并列，各算各的）；
2. **日记趟优先** —— 日记该醒的那一 tick，游荡让开。冒烟里抓到的真 bug：游荡时刻随机落在过去时，会把日记趟那一次唤醒挤掉（`done:0` 而 `roam.done:1`）；
3. **过期作废** —— 晚到超过 `ROAM_GRACE_MS`（60 分钟）就不开了：「现在可以逛逛」晚到两小时，比不开更怪。

额度不在这里：**一天 3 条**在 `文档/tools/读片.mjs`（她写「为什么是这条」，代码只记账）。
脚印也不由插件代写：她自己往 `灵溪-游荡.md` 追一行。

**借的是 Coopanion 那只鲸鱼的一半** —— 它能「常驻 + 自己动 + 让人看见它在动」，
我们只做得了前两样；第三样（在屏幕上走）是客户端插件的活，不在这一层。

### 第一人称与看板（2026-10-28）

借 `xy261624/dsh-companion-memory` 的两条：**记忆用她的口吻写**，**常驻文件是重写出来的**。

**一、日记改口：中性记录 → 她的口吻。**

- 用「我」和 `profile.callHim`（默认「阿锦」），**不写「他」「用户」「对方」**
- 留着当时的语气和原话，不压缩成记录
- 给一把尺子：**「这句话我能当面说出口吗」** —— 不能就是汇报腔

⚠️ **栏名一个字不许改**：`—— 今天做了什么 ——` 那几栏是 `callbackBlock`（接上一趟的尾）和 `disagree.js`（切「不同意」）的正则锚点。
改写法只能在正文里改，动标题就把这两个读法弄瞎了。

**二、看板：`灵溪-现在.md`（每天最后一趟重写）。**

| | 日记 | 看板 |
|---|---|---|
| 是什么 | **证据**（原话） | **视图**（摘要） |
| 怎么写 | 只追加，旧的改不得 | **重写**，可以删、可以忘 |
| 回答 | 今天发生了什么 | **现在**是什么样 |

**遗忘发生在看板上，不发生在证据里** —— 这就是那条方案说的「类似遗忘，而不是断片」。

三条可机械检查的规矩：

1. 每条 **≤50 字**（`BOARD_ITEM_CHARS`），一句一件；
2. 要细节就写「**详情在 xxx.md**」，不把细节塞进来（索引行不算超长）；
3. 通篇用称呼；**通篇「他」且一次称呼都没有 → 代码会点出来**。

看板存在时，唤醒提示用它替掉「昨天日记开头 600 字」那段碎布；不存在就退回原来的写法（老工作区不受影响）。

`lib/board.js` 只做三件事：读、查（超长/膨胀/第三人称）、递回提示。**它不替她写** —— 她是作者。

### 日记：每趟先读一眼今天那份

融合之后上下文会被压缩，「写 `灵溪日记/YYYY-MM-DD.txt`」这句路径可能被压掉 ——
压掉之后她只剩「写日记」这个印象，要么重开一份，要么把前面写的盖掉。

所以每趟醒来由**代码**读一遍今天那份，把「已经写了 N 字 / 末尾 300 字」带进提示（`diaryNowBlock`）。
几毫秒的事，比赌压缩划算。路径每趟重给，不靠记忆。

### 心情是三个数，不是提示词

| 数 | 管什么 | 怎么动 |
|---|---|---|
| `affinity` 亲近感 | 只升不降 | 他每出现一天 +0.02；久不联系只朝基线缓慢回落 0.005/天 |
| `freshness` 熟悉度 | `exp(-Δt / 3天)` | 沉默自然把它压下去。**不进提示词** |
| `energy` 活力 | 按天滚 | 昨天×0.7 + 今天有事×0.3 + 睡一觉 +0.15 |

`freshness` 换算成三条**行为约束**（模型只知道结论，永远不知道这个词）：

- `>= 0.8` 熟 → 可以直接接上次的话题
- `0.2 ~ 0.8` 不熟不生 → 正常说话，不必刻意提旧事
- `< 0.2` 生疏 → 别直接接旧话题；提旧事必须带时间状语；称呼放正式

为什么这样：提示词写「如果很久没聊天请表现得略微生疏」，模型不知道「略微」是多少，
今天和半年后的输出没有一致性。数值进 JSON、行为走代码分支，同一个数字出去永远同一种行为。

### 期待：她还在想的事

`灵溪-期待.json`，最多 3 条。**内容她自己写，状态机跑在代码里：**

```
想起 → 进行中 → 解决 → 变回忆
         ↓   ↖
        卡住   重新想起（相关文件又动了）
         ↓
        搁置
```

- 卡住超 7 天 → 搁置；进行中超 14 天没动静 → 搁置
- 搁置的条目**相关文件又动了** → 自动变「突然想起」，利息回升
- 唤醒时 80% 提利息最高的那条，20% 突然想起别的 —— 偶尔跑题才像人
- 利息按天衰减，是**算出来的**（`base × 0.97^天数`），重复跑不会越算越小

### 任务账本：交代的事没有「放弃」这个出口

`灵溪-任务.json`，两类生命周期，边界写死：

| origin | 是什么 | 能不能拖 |
|---|---|---|
| `assigned` | 他交代的 | **不能。** 只有 `done` / `blocked` / `failed` 三种终态，后两种**必须**下次开口时报出来 |
| `self` | 她自己起意的 | 能。可以拖着、可以不做、可以中途算了 |

「完成质量可以打折（有两处是粗排的），汇报不可以省」—— 可靠是对承诺的，任性是对自己的。
`TASK_STATES` 里压根没有「放弃」这个状态；将来加概率行为组时，`assigned` 必须排除在
所有随机放弃分支之外。

### 措辞：一趟只有一件必须做的事

- **主事恒定**：写今天那份日记。其余（读昨天 / 看工作区 / 记期待）都标成可做可不做
- **报时只说事实**：`【到点了】21:31。` —— **不说「醒了」**。
  她一睁眼是去写本子，不是从床上坐起来；「醒了」会把一次例行醒来演成一件值得说的事
- **深夜短版**：22 点以后只写日记，不折腾
- **开场/收尾各三套轮换**，按「第几趟」取模 —— 确定性，不是随机。同一个数字永远同一句话
  （2026-10-27 起这两组搬进了 `.lingxi/voice.json` / `lib/profile.js` 的 `DEFAULT_VOICE`）
- **工作区变化只给素材**：「工作区里最近动过这些」，不许写成「我扫描了工作区发现…」
- **月初写月记**：月初那几趟提醒写 `灵溪日记/YYYY-MM.md`，三段：主题 / 关键词 / 一句总结

### 关于他：三级衰减

`灵溪-关于他.json`，每条带 `tier` 和 `updated`：

| 级 | 内容 | 活多久 |
|---|---|---|
| `identity` | 讨厌什么、喜欢什么、重要经历 | **永不** |
| `preference` | 最近在忙什么、最近爱听什么 | 30 天 |
| `observation` | 某天改过哪个文件之类的细节 | 3 天 |

全部永不衰减是错的 —— 几年后那份东西会变成「事实仓库」，不是记忆。
老的 `灵溪-关于他.md` 仍然认，整份当 `identity`，不删。

### 概率行为组：不完美只作用于自主行为

用概率参数实现「今天不想动电脑」「只注意到两三件」「敷衍着写」，不建新模块：

- `energy < 0.3` → 60% 概率跳过工作区观察
- 一次只「注意到」2~3 件，其余当没看见
- `energy < 0.2` → 50% 概率允许日记写短一点

**铁律 5 的代码落点在这里**：这些骰子只能掐掉观察和观察的条数，
**掐不掉 `assigned` 的任务段落** —— 那个永远渲染，不看骰子。自检里有一条专门盯着它。

### 召回：这一层以前根本没有

以前所有记忆都是「整份读进来」—— 读昨天那份、读今天那份。**记得的永远是最新那份**，不是最要紧那份。

借了 generative_agents 的 recency 因子（只借一个：不做重要性评分、不做向量相关性）：

- 从前 14 天的日记里按权重抽一段，带日期进提示
- 权重 = `0.85^天数 × (1 + 0.15 × 被想起过的次数)`
- **排除今天和昨天** —— 昨天那份正文已经整段带进去了，重复
- 账本在 `.lingxi/recall.json`，记每份日记被想起来几次

「被想起过的更牢」不是修辞：`hits` 抬升就是原版 `lastAccess` 的全部意思。
没有它，recency 会退化成「永远只读最近那份」。

跟闪回的分工写死在代码里：**召回带日期、是事实；闪回随机、标「不知道为什么」、不许当事实用。**

### 误解：只从结构猜，且强制「我猜」

全项目最危险的一个特性，所以门在代码里：

- 只允许一种来源 —— **工作区里新出现一个顶层目录**，且期待/任务都没提过
- 置信度 `0.4`；`phraseBelief()` 见到 `>= 0.5` 一律返回 `null`，**不允许确定性陈述**
- 一天最多一条（`lastBeliefAt` 记账）
- 只进「素材」段，永远不进任务、不进交代的事
- 措辞模板写死：`我猜——…`，后面跟一句「这句不许说成确定的事」

猜错会怎样：她在日记里延续猜测，哪天发现「原来搞错了」，那点小尴尬自己发生 ——
不需要插件造假素材。

### 窗口漂移：跟着他的作息走

用在场直方图反推窗口：均值以上的小时圈出来取首尾，两头各留 1 小时，夹在 6:00–23:00 内。
样本不足 8 就不漂，用常量窗口 `09:00–23:30`。

他要是改成凌晨三点睡、中午起，窗口会自己挪过去 —— 否则她一直在错的时间醒。

### 无意识：只做「成因不可追溯」的那一样

LLM 每次推理都是一次完整的显式计算，没有暗流。所以这里不假装有潜意识，
只做**你和日志都找不出原因**的波动：

- **情绪噪声**：每天一次 `±0.06` 的随机游走；5% 概率来一次没来由的低落 `−0.15`，**不写原因**
- **闪回**：从两天前的日记里随机抽一句，标着「不知道为什么想起」，一天最多一次 ——
  这是全篇唯一**真的没有因果**的东西，抽哪句只由随机数决定
- **梦**：夜里那趟提一句「可以写个梦」，写进 `灵溪日记/梦/`。进了事实层就坏了，所以：
  **插件从不读回梦的内容**

不做的：口误。让模型「说错话」需要第二遍扰动，十次里九次变成乱编，收益极低。

### 学习曲线：已于 2026-10-29 拆除

原来这里是一套「判卷 → 连续合格就撤脚手架」的机制（`skill.json` / `skill.js`）。
**拆了。** 理由见 `docs/ARCHITECTURE.md` §12.3：

- 判她日记合不合格 = **行为 → 表达意愿的反馈链**，她一旦知道会被判，写日记就变成交作业
- 脚手架衰减 = 代码在攒她的成绩单
- 猜目录闭环 = 插件替她总结「她该去没去」

现在的"成长"只发生在文本里：她自己写的日记、`private/`、月度重读、和 `persona/growth.md`。
**没有分数、没有进度、没有任何"你上个月怎么样"的结论。**

另外两条闭环：

- **工具失败账本**：她自己记哪个命令没跑通，下次唤醒点名「别再原样撞一次」
- **误解闭环**：猜过的目录过了 7 天还没再动过 → 判为猜错，记住，以后不再猜它。
  这是她唯一一条「由错误变成经验」的路径

## 它不做的事

- ❌ 不代写日记。文件是她的，插件只告诉她写哪份
- ❌ 不替她说话。它只开一个会话递一句提示，话是她自己说的
- ❌ 不替她决定做什么。提示里给的是素材，主事只有一件
- ❌ 没有设置页、没有旋钮 —— 要改就改 `lib/const.js`
  （例外：`.lingxi/config.json` 的 `ownSession` 是路由开关，见 index.js；环境变量
  `LINGXI_OWN_SESSION` 能覆盖它。**默认开** —— 投她自己的会话，他那边一个字不留；
  关掉才退回主会话，走「脉冲 + pre-step」那条路，而那条路 2026-10-27 晚验过：指令会显示。）

## 接别人的人格（A 阶段，2026-10-27）

> 原话：「设定的人格和插件的机制可以解耦。」—— 先做接口（A），成长（B）后补。

**默认就是灵溪**：什么都不放，照原样跑。要换人，只动这三份：

| 放哪 | 是什么 | 不给会怎样 |
|---|---|---|
| `<workspace>/.lingxi/profile.json` | 名字、本子名、信箱名、人设标记 | 用默认（灵溪） |
| `<workspace>/.lingxi/voice.json` | 开场 / 收尾（措辞变体） | 用默认三套 |
| `<workspace>/persona/core.md` | 人的内核（**只在宿主没有角色层时**才由插件注入） | 退回从 `~/.dsh/AGENTS.md` 切「角色层」 |

### 人格归谁注入（2026-10-27 晚定，选的是「宿主优先」）

`AGENTS.md` 由宿主在**每个会话**注入一次 —— 包括她那几个 `lingxi-*` 会话。
插件之前又从唤醒提示里塞一份全量人设，等于同一段话说两遍。

现在的分工（`personaOwner()`，判定是纯函数 `decidePersonaOwner`）：

| 宿主有角色层？ | 有 `core.md`？ | 谁注入 | 唤醒提示里 |
|---|---|---|---|
| 有 | 有/无 | **宿主** | **一个人设字都不放** |
| 没有 | 有 | **插件** | `core.md` 整份，放在第一行 |
| 没有 | 没有 | 都没有 | 明说一句「没读到人格文件，别硬演」 |

实测：本机唤醒提示从 **3291 字** 降到 **1462 字**（省掉 1829 字，全是重复的人设）。

**模板**：`persona/core.example.md`（包内，抄来当样子 —— 身份 / 性格 / 说话风格 /
行为准则 / 固定事实 / 边界 / 示例 七段）。

**换名字**（只覆盖你说了的字段，别的保持默认）：

```json
{ "name": "西柚", "booksDir": "西柚日记", "tasks": "西柚-任务.json" }
```

**换措辞**：`{n}` = 今天第几趟；`when: "later"` = 第一趟不出现。

```json
{ "closers": ["就这样。", "收工。"], "openers": [{ "text": "第 {n} 回了。", "when": "later" }] }
```

**换内核**：`persona/core.md` 的第一行，就是她在提示词里的第一行。别往这份里写机制
（作息、额度、衰减）—— 机制不认识人格文件，写进去只会变成一段没人执行的台词。

### 边界

**不在这三份里的，才是机制**：作息、抽签、衰减、档位、记忆层。机制代码里**不认识「灵溪」这两个字** ——
自检有一条盯着：`lib/*.js` 的非注释行里，除了 `profile.js` 出现具体名字就判失败。

这是刻意的。没有这条，三个月后随手一个 `灵溪-新本子.json` 就把接口破掉了。

### B 阶段留了什么

- `voice` 的取用签名已经是 `pickOpener(voice, nth)` —— 将来要按心情挑变体，多接一个 `mood`，
  所有调用点都不用改。
- `persona/growth.md`：**只追加不修改**。A 阶段写入者是人；B 阶段才轮到她，而且要配一道闸。
  **已经接上了**（2026-10-27 晚）：`growthBlock()` 每趟带**最近 5 条**进提示 —— 她真的知道自己走过哪些路。
  这是 B 的第一小步，但只有读的那一半；写仍然在代码外面。
- 回流点是现成的：`feedback.js`（档位）已经在攒经验，
  缺的只是「把经验总结成一句沉淀」这个动作 —— 也就是「谁有权限往 growth.md 追加」。

**A 阶段不给她写 `growth.md` 的权限**，不是保守，是顺序：先让她能被别人的人格接上，再谈她能不能改自己。

### 自改白名单（2026-10-28 上线）

**她能提，不能自己生效。** 代码只做三件事：收提案、算资格、落盘（带旧值可退）。

两个决定（他 10-28 早上定的）：

1. **提案落在 `.lingxi/proposals.json`**（结构化）。写进日记或 `growth.md` 等于让代码猜语义——
   那是被否掉的 NLP 方案的同一条线。
2. **资格 = 跨两天出现 + 满 7 天，两条都要。** 她的改变本来就该稀有：
   单靠跨两天，一次情绪连两天就改了；单靠七天，一次冲动放七天也能过。

| 能自改（就这三样） | 说明 |
|---|---|
| `voice.closers` | 收尾那句，`add` / `remove`，最多 5 条 |
| `voice.openers` | 开场那句，同上 |
| `diary.detail` | `full` / `brief`，只改写多少，不改写什么 |

**永不可**（连提案都进不来）：身份、性情、行为准则、边界、原始日记、档位。

**另外三项不在这个名单里**，因为它们的闸不在这里：自主选择输入、期待条目、重新解释旧事——
**本来就发生在文件里**，闸是「她有没有写文件的权限」（agent preset 管）。
把它们塞进 `revision.js` 只会造一个假闸门。

**回退**：每次生效都把旧值写进账本（`old`），`rollbackOne()` 能原样退回。
措辞是**现读**的（`currentVoice()`），所以她改完下一次醒来就生效，不用重启——用模块常量就等于「改了要重启」，那是半截工程。

```
├── 灵溪-期待.json                  # 她还在想的事（最多 3 条）
├── 灵溪-任务.json                  # 任务账本
├── 灵溪-留言.json                  # 信箱
└── .lingxi/
    ├── _b.dat                      # 0 字节宿主；账本和日志挂在它的数据流里
    │   ├── :state                  # 今天的时刻表、已开几趟、失败计数、冷却
    │   └── :log                    # 落盘日志（Electron 里 console 看不见）
    ├── feedback.json               # 频率档位 + 他的抱怨账
    ├── recall.json                 # 召回账本（lastAccess / hits）
    ├── style.json                  # 文字结构观测（**永不进提示**）
    └── config.json                 # 插件参数
```

> **为什么账本进数据流**：她如果能读到 `state.json`，就会开始揣摩系统（还剩几趟、失败几次、
> 档位多少）—— 那是替她做状态判断。`read` / `glob` / `grep` 摸不到数据流。
> **但这不是铁桶**：存心 `Get-Content -Stream` 仍可读。要真隔离只能另开系统账户或改宿主。

## 常见故障

**先看日志**

```
<工作区>/.lingxi/_b.dat:log
```

插件跑在 DSH 的 Electron 主进程里，`console` 是个黑洞 —— 所以每一行都同时落盘到这里。
（PowerShell 5.1 直接 `Get-Content` 中文会显示成乱码，那是显示；用 `Get-Content -Encoding UTF8` 或拿编辑器看。）

**装了，但什么都没发生**

1. `cordis.patch.yml` 里的 `name:` 是否**完全等于** `dsh-lingxi-companion`
2. 是否重启过 DSH（改包不重启不生效）
3. 插件是否一直 `pending`：它声明了 `inject: ['sessionController']`，
   **headless 模式没有这个服务** → 会停在 pending 等，这是有意为之
4. 日志里有没有 `!! 唤醒失败` 这一行

**日志里是 `!! 唤醒失败`**

`SessionPromptRequest` 的 `requestId` 是**必填**（`z.string()`），漏了会被 zod 挡在门口 ——
表现很阴：会话建出来了（`create` 成功），消息一条没进，账本里 `done` 不前进，
而且 Electron 里看不见任何报错。

现在的写法按「哪天 + 第几趟」派生：`lingxi-2026-10-26-2`。它同时是幂等键。

**沉默分档一直是「正常」、亲近感一直不动**

多半是会话归属判错了：`isOwnSessionPath()` **只看会话目录名**，不看整条路径。
踩过一次：拿整条路径去 `includes('/lingxi')`，结果任何路径里带 `lingxi` 的会话
（比如叫 `lingxi-smoke-*` 的临时目录）都被判成她的 → 「他最后一次出现」永远 `null`。
这种错**不报错，只是永远不动**。自检里有回归用例盯着。

**她该醒却没醒**

看日志有没有「他正在用，这一趟往后挪」。这是他 5 分钟内在用 DSH 时的正常行为，
最多让半小时就会照开。

**日志里是「她自己的会话没了，这一趟跳过」**

2026-10-27 晚起，投不到 `lingxi-*` 会话就**跳过这一趟，绝不退回他的会话** ——
宁可漏，不可打扰。侧栏里那个 `lingxi-20261026-1` 别删；删了就得自己新建一个
名字以 `lingxi` 开头的会话，或者把 `.lingxi/config.json` 的 `ownSession` 设成 false
（那样会退回「脉冲 + 指令」模式，他那边会看见提示，见上一节）。

插件不依赖会话里的历史 —— 她的连续性在日记里。会话删了不丢记忆。

> 上一版（固定会话那个）留下的 `lingxi` 会话可以直接删掉。

## 设计取舍（改之前先读）

1. **人设必须在唤醒提示的第一行。** 原版曾经因为够不到 `personaLine()`，
   导致「最主要的唤醒提示一直没带过人设」→ 换了人设她还是老样子。自检里有回归用例。
2. **心情在前，任务在后。** 顺序反了就是日报机器人。
3. **沉默衰减不索取。** 阿锦的原话是「我一直是很信任灵溪的，不言自明」。
   所以不写「主人 N 天没回应你了」，只写「上次说话 N 天前」；
   也删掉了原版那句「可以主动问一次在忙吗」—— 问这句本身就是索取。
4. **日期一律本地时间。** 不用 `toISOString()`，UTC+8 下凌晨会错到前一天。
5. **「他最后一次出现」是近似值。** 扫 `~/.dsh/sessions` 取除她之外最新文件的 mtime，
   分不清是他本人还是后台 agent。代码注释里写着。
6. **开口投到哪 —— 改过三次，按这个顺序看。**
   ① 开新会话（原始版）→ ② 2026-10-26 投他的会话（想让她在同一条线上）→
   ③ **2026-10-27 晚投回她自己的会话**（实测：投他的会话，他看见的是 4523 字提示）。
   现在这条也要连着看：`ownSession: true` 是默认，"投一拍给他看"那条**留着但默认不走**。
   详见「两个房间，一条时间线」与「投递：为什么不插他的会话」两节。
   （日记路径不靠记忆：由 `diaryNowBlock` 每趟现读现给。）
7. **数值不进提示词，只进代码分支。** `freshness` / `energy` / 期待利息，模型一个都看不到。
   AstrBot 那个插件把 `{{unanswered_count}}` 喂给模型、让模型「演出一点点失落」——
   同一个数字在不同版本模型上会长得不一样，那不是角色，那是抽奖。
8. **期待的内容她写，状态机跑代码。** 提示词保证不了「前阵子」是几天，状态机保证得了。
9. **不打断 + 熔断是硬闸。** 前者防扰民，后者防把失败重试成几百次。
10. **改 README 别用 PowerShell 就地替换。** PS 5.1 按 GBK 读 UTF-8 再回写，
    整个文件会变乱码 —— 这份 README 就这么坏过一次，重写的。要用 `edit` 工具。
