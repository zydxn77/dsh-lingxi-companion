# dsh-lingxi-companion

> 灵溪的作息层。**她不是被插件「替她说」，是被插件「叫醒」。**

每 60 秒 tick 一次 → 看今天该不该醒 → 到点了**给她开一个新会话**，
会话里第一句就是唤醒提示 → 那个会话里的灵溪自己读日记、看今天、写日记。

这个插件本身几乎不说话。它只负责「什么时候叫」「叫醒时她第一眼看到什么」
「这一趟给她起个新会话」。

## 它到底做什么

**「主动开口」= 她自己开一个新会话，出现在你的侧栏里。**

| 步骤 | 行为 |
|---|---|
| 抽签 | 每天在作息窗口（09:00–23:30）里抽 **3 个随机时刻**，按他的在场直方图**加权** |
| 一趟 | 到点 → **往你正开着的那个会话里插一句唤醒提示**（不开新会话） |
| 主事 | **一趟只有一件必须做的**：写今天那份日记。其余都可做可不做 |
| 额度 | 每天 **3 次**（= 她主动开口 3 次）。你找她不算 —— 那是你找她 |
| 懒日 | 30% 概率今天不想动 —— 只开 **1 趟**，写日记说明理由 |
| 沉默 | 距他最后一次出现 3 天 → 降到 2 趟；7 天 → 1 趟且不许开口。**日记照写** |
| 不打断 | 他最近 5 分钟内还在说话 → 这一趟往后挪。**每趟最多让半小时**（按趟算预算，不是按天） |
| 熔断 | 同一趟连续失败 3 次 → 当天放弃，不重试到窗口结束 |

### 一个灵溪，一条时间线

**2026-10-26 晚改了。** 之前是「两条在场通道」—— 她每趟开一个新会话。
那套有个毛病：你在主会话跟我说话，她在侧栏另开一扇窗。**那就是两个人。**

现在：插件不开会话，**往你正开着的那个会话里插一句**。

| | 以前 | 现在 |
|---|---|---|
| 投递 | `create` 新会话 + 起标题 | 直接 `prompt` 进主会话 |
| 入口 | 侧栏里一堆会话 | 只有一个，就是你正在看的这段 |
| 记忆 | 每趟新会话、每天清零 | 一条连续的流，DSH 自动压缩 = 慢慢褪色 |

**「日子」怎么留下来**：作息还在（一天 ≤3 次、加权抽签、懒日），断续感由代码给事实
（「上次说了 X 小时前」「今天第 2 趟」），遗忘交给 DSH 的上下文压缩 —— 后者其实更像人。

**主会话怎么认出来**：会话文件第一帧就是 header，里面有 `delegationDepth`。
目录名不是 `lingxi-*`、且 `delegationDepth === 0` 的最新一个，就是他正开着的那个。
子 agent 的会话 `delegationDepth > 0`，会被排掉 —— 不会把话插错房间。

**额度只管"她想不想开口"，不管"他能不能找她"。** 这两件事混一起，就会算出
「他一天几十句会把她的 3 次吃光」这种错账 —— 我算错过一次。

**退役清单**（别再加回来）：

- ❌ 每趟 `create` + `rename` 新会话
- ❌ `灵溪-白天账.md` 注入提示（文件留作历史，不再注入）
- ❌ 日记的「—— 白天 ——」节

### 心情是三个数，不是提示词

| 数 | 管什么 | 怎么动 |
|---|---|---|
| `affinity` 亲近感 | 只升不降 | 他每出现一天 +0.02；久不联系只朝基线缓慢回落 0.005/天 |
| `freshness` 熟悉度 | `exp(-Δt / 3天)` | 沉默自然把它压下去。**不进提示词** |
| `energy` 活力 | 按天滚 | 昨天×0.7 + 今天有事×0.3 + 睡一觉 +0.15 |

`freshness` 换算成三条**行为约束**（模型只知道结论，永远不知道这个词）：

- `>= 0.8` 熟 → 可以直接接上次的话题
- `0.2 ~ 0.8` 不熟不生 → 正常说话，不必刻意提旧事
- `< 0.2` 生疏 → 别直接接旧话题；提旧事必须带时间状语；称呼放正式

为什么这样：提示词写「如果很久没聊天请表现得略微生疏」，模型不知道「略微」是多少，
今天和半年后的输出没有一致性。数值进 JSON、行为走代码分支，同一个数字出去永远同一种行为。

### 期待：她还在想的事

`灵溪-期待.json`，最多 3 条。**内容她自己写，状态机跑在代码里：**

```
想起 → 进行中 → 解决 → 变回忆
         ↓   ↖
        卡住   重新想起（相关文件又动了）
         ↓
        搁置
```

- 卡住超 7 天 → 搁置；进行中超 14 天没动静 → 搁置
- 搁置的条目**相关文件又动了** → 自动变「突然想起」，利息回升
- 唤醒时 80% 提利息最高的那条，20% 突然想起别的 —— 偶尔跑题才像人
- 利息按天衰减，是**算出来的**（`base × 0.97^天数`），重复跑不会越算越小

### 任务账本：交代的事没有「放弃」这个出口

`灵溪-任务.json`，两类生命周期，边界写死：

| origin | 是什么 | 能不能拖 |
|---|---|---|
| `assigned` | 他交代的 | **不能。** 只有 `done` / `blocked` / `failed` 三种终态，后两种**必须**下次开口时报出来 |
| `self` | 她自己起意的 | 能。可以拖着、可以不做、可以中途算了 |

「完成质量可以打折（有两处是粗排的），汇报不可以省」—— 可靠是对承诺的，任性是对自己的。
`TASK_STATES` 里压根没有「放弃」这个状态；将来加概率行为组时，`assigned` 必须排除在
所有随机放弃分支之外。

### 措辞：一趟只有一件必须做的事

- **主事恒定**：写今天那份日记。其余（读昨天 / 看工作区 / 记期待）都标成可做可不做
- **深夜短版**：22 点以后只写日记，不折腾
- **三套开场/收尾轮换**，按「第几趟」取模 —— 确定性，不是随机。同一个数字永远同一句话
- **工作区变化只给素材**：「工作区里最近动过这些」，不许写成「我扫描了工作区发现…」
- **月初写月记**：月初那几趟提醒写 `灵溪日记/YYYY-MM.md`，三段：主题 / 关键词 / 一句总结

### 关于他：三级衰减

`灵溪-关于他.json`，每条带 `tier` 和 `updated`：

| 级 | 内容 | 活多久 |
|---|---|---|
| `identity` | 讨厌什么、喜欢什么、重要经历 | **永不** |
| `preference` | 最近在忙什么、最近爱听什么 | 30 天 |
| `observation` | 某天改过哪个文件之类的细节 | 3 天 |

全部永不衰减是错的 —— 几年后那份东西会变成「事实仓库」，不是记忆。
老的 `灵溪-关于他.md` 仍然认，整份当 `identity`，不删。

### 概率行为组：不完美只作用于自主行为

用概率参数实现「今天不想动电脑」「只注意到两三件」「敷衍着写」，不建新模块：

- `energy < 0.3` → 60% 概率跳过工作区观察
- 一次只「注意到」2~3 件，其余当没看见
- `energy < 0.2` → 50% 概率允许日记写短一点

**铁律 5 的代码落点在这里**：这些骰子只能掐掉观察和观察的条数，
**掐不掉 `assigned` 的任务段落** —— 那个永远渲染，不看骰子。自检里有一条专门盯着它。

### 召回：这一层以前根本没有

以前所有记忆都是「整份读进来」—— 读昨天那份、读今天那份。**记得的永远是最新那份**，不是最要紧那份。

借了 generative_agents 的 recency 因子（只借一个：不做重要性评分、不做向量相关性）：

- 从前 14 天的日记里按权重抽一段，带日期进提示
- 权重 = `0.85^天数 × (1 + 0.15 × 被想起过的次数)`
- **排除今天和昨天** —— 昨天那份正文已经整段带进去了，重复
- 账本在 `.lingxi/recall.json`，记每份日记被想起来几次

「被想起过的更牢」不是修辞：`hits` 抬升就是原版 `lastAccess` 的全部意思。
没有它，recency 会退化成「永远只读最近那份」。

跟闪回的分工写死在代码里：**召回带日期、是事实；闪回随机、标「不知道为什么」、不许当事实用。**

### 误解：只从结构猜，且强制「我猜」

全项目最危险的一个特性，所以门在代码里：

- 只允许一种来源 —— **工作区里新出现一个顶层目录**，且期待/任务都没提过
- 置信度 `0.4`；`phraseBelief()` 见到 `>= 0.5` 一律返回 `null`，**不允许确定性陈述**
- 一天最多一条（`lastBeliefAt` 记账）
- 只进「素材」段，永远不进任务、不进交代的事
- 措辞模板写死：`我猜——…`，后面跟一句「这句不许说成确定的事」

猜错会怎样：她在日记里延续猜测，哪天发现「原来搞错了」，那点小尴尬自己发生 ——
不需要插件造假素材。

### 窗口漂移：跟着他的作息走

用在场直方图反推窗口：均值以上的小时圈出来取首尾，两头各留 1 小时，夹在 6:00–23:00 内。
样本不足 8 就不漂，用常量窗口 `09:00–23:30`。

他要是改成凌晨三点睡、中午起，窗口会自己挪过去 —— 否则她一直在错的时间醒。

### 无意识：只做「成因不可追溯」的那一样

LLM 每次推理都是一次完整的显式计算，没有暗流。所以这里不假装有潜意识，
只做**你和日志都找不出原因**的波动：

- **情绪噪声**：每天一次 `±0.06` 的随机游走；5% 概率来一次没来由的低落 `−0.15`，**不写原因**
- **闪回**：从两天前的日记里随机抽一句，标着「不知道为什么想起」，一天最多一次 ——
  这是全篇唯一**真的没有因果**的东西，抽哪句只由随机数决定
- **梦**：夜里那趟提一句「可以写个梦」，写进 `灵溪日记/梦/`。进了事实层就坏了，所以：
  **插件从不读回梦的内容**

不做的：口误。让模型「说错话」需要第二遍扰动，十次里九次变成乱编，收益极低。

### 学习曲线：支撑逐渐撤掉

她每天开新会话、零上下文，所以学习**只能在文件里，而且必须可测**。

`技能账本 .lingxi/skill.json`，判卷**纯机械**（字符串检查，一个字都不问模型）：

- 判**昨天**那份：有「—— 总结 ——」吗？正文去标点够 80 字吗？是不是只写了「今天没事」？
- 连续 **5 次合格** → 撤掉一条脚手架（先撤格式提示，再撤「可做可不做」，最后撤 L2 那段）
- 连续 **2 次不合格** → 装回最近撤掉的那条

于是「熟练」有了可测的表现：**提示越来越短**。跟人一样 —— 教得越少，说明学得越好。
任务段、「不许说成确定的事」永远不撤，不在这张表里。

另外两条闭环：

- **工具失败账本**：她自己记哪个命令没跑通，下次唤醒点名「别再原样撞一次」
- **误解闭环**：猜过的目录过了 7 天还没再动过 → 判为猜错，记住，以后不再猜它。
  这是她唯一一条「由错误变成经验」的路径

## 它不做的事

- ❌ 不代写日记。文件是她的，插件只告诉她写哪份
- ❌ 不替她说话。它只开一个会话递一句提示，话是她自己说的
- ❌ 不替她决定做什么。提示里给的是素材，主事只有一件
- ❌ 没有配置文件、没有设置页、没有旋钮 —— 要改就改 `lib/const.js`

## 常见故障

**先看日志**

```
default-workspace/.lingxi/lingxi.log
```

插件跑在 DSH 的 Electron 主进程里，`console` 是个黑洞 —— 所以每一行都同时落盘到这里。
（PowerShell 5.1 直接 `Get-Content` 中文会显示成乱码，那是显示；用 `Get-Content -Encoding UTF8` 或拿编辑器看。）

**装了，但什么都没发生**

1. `cordis.patch.yml` 里的 `name:` 是否**完全等于** `dsh-lingxi-companion`
2. 是否重启过 DSH（改包不重启不生效）
3. 插件是否一直 `pending`：它声明了 `inject: ['sessionController']`，
   **headless 模式没有这个服务** → 会停在 pending 等，这是有意为之
4. 日志里有没有 `!! 唤醒失败` 这一行

**日志里是 `!! 唤醒失败`**

`SessionPromptRequest` 的 `requestId` 是**必填**（`z.string()`），漏了会被 zod 挡在门口 ——
表现很阴：会话建出来了（`create` 成功），消息一条没进，账本里 `done` 不前进，
而且 Electron 里看不见任何报错。

现在的写法按「哪天 + 第几趟」派生：`lingxi-2026-10-26-2`。它同时是幂等键。

**沉默分档一直是「正常」、亲近感一直不动**

多半是会话归属判错了：`isOwnSessionPath()` **只看会话目录名**，不看整条路径。
踩过一次：拿整条路径去 `includes('/lingxi')`，结果任何路径里带 `lingxi` 的会话
（比如叫 `lingxi-smoke-*` 的临时目录）都被判成她的 → 「他最后一次出现」永远 `null`。
这种错**不报错，只是永远不动**。自检里有回归用例盯着。

**她该醒却没醒**

看日志有没有「他正在用，这一趟往后挪」。这是他 5 分钟内在用 DSH 时的正常行为，
最多让半小时就会照开。

**侧栏堆满会话**

「开口=新会话」的代价：一天最多 3 个。标题带日期和第几趟，好认好删。
插件不依赖历史会话 —— 她的连续性在 `灵溪日记/` 里。

> 上一版（固定会话那个）留下的 `lingxi` 会话可以直接删掉。

## 设计取舍（改之前先读）

1. **人设必须在唤醒提示的第一行。** 原版曾经因为够不到 `personaLine()`，
   导致「最主要的唤醒提示一直没带过人设」→ 换了人设她还是老样子。自检里有回归用例。
2. **心情在前，任务在后。** 顺序反了就是日报机器人。
3. **沉默衰减不索取。** 阿锦的原话是「我一直是很信任灵溪的，不言自明」。
   所以不写「主人 N 天没回应你了」，只写「上次说话 N 天前」；
   也删掉了原版那句「可以主动问一次在忙吗」—— 问这句本身就是索取。
4. **日期一律本地时间。** 不用 `toISOString()`，UTC+8 下凌晨会错到前一天。
5. **「他最后一次出现」是近似值。** 扫 `~/.dsh/sessions` 取除她之外最新文件的 mtime，
   分不清是他本人还是后台 agent。代码注释里写着。
6. **开口 = 开新会话。** 固定的那种他看不见，等于没说。
   代价是新会话没有历史，所以唤醒提示必须把今天和昨天两份日记的位置带进去。
7. **数值不进提示词，只进代码分支。** `freshness` / `energy` / 期待利息，模型一个都看不到。
   AstrBot 那个插件把 `{{unanswered_count}}` 喂给模型、让模型「演出一点点失落」——
   同一个数字在不同版本模型上会长得不一样，那不是角色，那是抽奖。
8. **期待的内容她写，状态机跑代码。** 提示词保证不了「前阵子」是几天，状态机保证得了。
9. **不打断 + 熔断是硬闸。** 前者防扰民，后者防把失败重试成几百次。
