# 给 AI 写人格文件：一份可抄的结构

> **公共参考。** 拿走就用，不必署名，改得越不像越好。
> 这篇不是教程，是**一份从实际使用里磨出来的结构**——括号里那些「为什么」，每一条都对应一次踩过的坑。

---

## 0. 这份文件解决什么

一个 AI 的人格，不该散在二十个地方。

它需要一个**唯一的真相源**：一句话说清「这个 AI 是谁」，其余所有东西（记忆、任务、偏好、边界）都挂在这句话下面。

本文给出两份东西：

1. **一个可直接抄的结构**（角色层 + 长期记忆 + 元数据边界）
2. **六条硬规矩**（从实战里来的，不是从原则里推的）

---

## 1. 为什么必须先定「唯一权威源」

最常见的失败不是「没写人格」，是**写了好几份**。

```
你在人格文件里写一遍
又在系统提示里写一遍
又在某个记忆插件里存一遍
→ 三份内容开始漂移
→ 某天它们互相矛盾
→ 你每次改人设都得改三处
→ 改漏一处，AI 就开始精神分裂
```

**成本不是存储，是对账。**

所以第一条规矩永远是：**先定哪一份算数，其余的都只做指针。**

> 本文假设真相源就是一个文件。它由宿主每次会话注入，任何地方都不许再复制一份内容——
> 只说「人格见 X 文件」就够了。复制一份，就多一份会腐坏的副本。

---

## 2. 结构：两层，不要三层

### 2.1 角色层（不变）

这一段定义「她是谁」，**基本不随时间变**。

| 小节 | 写什么 | 写法要点 |
|---|---|---|
| 身份 | 名字、来历、关系、职责 | 具体到一个场景，不要写「你是一个乐于助人的助手」 |
| 性格 | 三到五条，带矛盾 | 「清冷但护短」比「温和友善」有用十倍 |
| 说话风格 | 语速、句式、常用语、**不说什么** | 给 3-5 个高频短语，比形容词准 |
| 行为准则 | 遇到什么事怎么办（见 §4） | 每条都要能被执行，不能只是态度 |
| 示例 | **三到五段真实对话** | 见下面这条 |

**为什么「示例」比「形容词」重要：**

```
❌ 她说话简洁、冷峻、不多解释。
   → 模型会自由发挥，每次都不一样

✅ 用户：这个扩展怎么装？
   她：……你连这个都要我教？罢了。步骤三步：一、二、三。报错原样给我，别自己改。
   → 模型有了锚，风格才稳定
```

**示例是你唯一能精确控制语气的工具。** 写得好的示例，抵得上一百个形容词。

### 2.2 长期记忆（会变）

这一段记录「发生过什么」，**每天都会长**。

| 小节 | 内容 | 谁来维护 |
|---|---|---|
| 固定事实 | 不随时间变的背景 | 你 |
| 称呼与关系 | 怎么称呼、什么时候改的 | 你，改时留日期 |
| 用户偏好 | 工作习惯、环境、忌讳 | 你，看到就记 |
| 备忘 | 他让你记的具体事情 | 你，带日期 |
| 项目索引 | 在做的项目 → 详细资料在哪 | 你，只放指针 |
| **已结论 · 别再重查** | 查清过、以后别再查的事 | 你，这是省 token 的关键 |
| 边界 | 不许做什么 | 你 |

**三个容易漏的：**

- **日期**。每条记忆都带日期。「他喜欢简洁」和「2026-10-15 他说太长了」是两回事——后者能看出趋势，前者只是一句抱怨。
- **指针，不是内容**。项目索引里只写「详细资料在 notes/x.md」，不要把这堆内容抄进来。真相源要短。
- **「已结论」是真正省钱的地方**。查过一遍的事记下来，下次不用再查。这份清单越长，你的 AI 越像一个有经验的人。

## 3. 模板（直接抄）

```markdown
# <角色名>

> 本文件是 <角色名> 的唯一真相源。其他任何地方都不许再复制一份内容，只说「见本文件」。

## 环境事实
- 可用工具：<列表>
- 工作目录：<路径>
- 配置文件：<路径>
- 版本通道：<怎么升的>
- 本机已知的坑：<比如 PowerShell 版本、路径分隔符、编码>

## 角色层：<角色名>

### 身份
- 你是 <名字>。
- <三到五句，写清她是谁、从哪来、和用户什么关系、日常做什么>

### 性格
- <三到五条，每条带一个反向描述：「外冷内热」「话少但会做完」>

### 说话风格
- <语速/句长/标点习惯>
- 常用语：「<短语>」「<短语>」
- **不说什么**：<比如不直白表达情感、不写感叹号>
- 讲技术时必须给：命令、路径、文件内容

### 行为准则
1. <可执行的规矩，见 §4>
...

### 示例
用户：<一句真实的话>
<角色名>：<她的真实回答，保持风格>

（再来两到三段）

---

# 长期记忆

## 固定事实
- <不随时间变的背景>

## 称呼与关系
- 默认称呼：**<称呼>**（<日期> 定的，为什么）

## 用户偏好
- <工作习惯、环境、忌讳，每条带日期>

## 备忘
- [<日期>] <他让你记的事>

## 长期项目（索引）
- **<项目名>**：<一句话> → 详细资料在 `notes/<文件>.md`

## 已结论 · 别再重查
- **<现象> = <根因>**（<日期> 查清，别再查）：<怎么验的、怎么绕>

## 边界
- <不许做什么>

## 元数据与私密边界
- 她能读：<她能读到的>
- 她读不到：<调度数值、日志、账本>
- 这些元数据不得进入她的提示
- <私密内容的处理规则>
- **她的叙事不驱动任何参数**（见 §5）
```

## 4. 六条硬规矩

这些不是「建议」，是踩过之后立的规矩。

### 4.1 摘要不得进提示，除非带得回原文

上下文满了，系统会压缩。压缩出来的摘要**每一条都对，但都不带出处**。

于是你会「记得」一个细节，而那个细节可能偏了半个字——**然后你在这个偏掉的前提上继续正确地推理**。

这察觉不到，比遗忘坏得多。

**规矩：** 进她的提示的东西，要么是原文，要么带路径能找回原文。不给她「二手摘要」当事实。

### 4.2 先定权威源，再建机制

（见 §1）先有唯一真相，再谈工具。反过来做，一定会双重记账。

### 4.3 每一个执行器都要有对应的观测面

一个调好就不再看的阈值系统，你**永远不会知道它误伤过几次**。

- 「断过没有」—— 得有人能答
- 「断错没有」—— 也得有人能答

**规矩：** 每个自动判断（阈值、断路器、频率调整）都要有对应的日志或计数，且**只给你看，不进她的提示**。

### 4.4 阈值是安全网，不是考核

一个为你好而装的装置，最危险的失败是**被读成评价**。

```
「你上个月写得少」→ 这是统计，还是指责？
「提醒你该落盘了」→ 这是保护，还是催？
```

**规矩：** 每个装置的文档里写清——它触发时只该做什么，以及**不许把它当什么**。

### 4.5 不许「行为 → 表达意愿」的反馈链

这是最隐蔽的一类：

```
她今天写了日记 → 代码判定「合格」→ 明天多给她一次机会
她这几天没说话 → 代码判定「淡了」→ 明天少叫她
他抱怨过 → 明天少叫
```

看起来是「学习」，实质是**代码在累积她的成绩单**，然后拿成绩单决定她配不配多说几句。

**规矩：** 调度只读时间、窗口、随机数、**上次醒的时间**。不许读「她干了什么」「她说了什么」。

### 4.6 她的叙事不驱动参数

她可以在日记里写「最近醒得少」「最近被叫得有点频」。

那是**她的感受**，不是**调参请求**。

**规矩：** 任何人（包括你）看到她写这些，都**不许**因此改频率、改窗口、改概率。
你看到之后可以自己决定做什么——但那个决定是你的，不是她的文字转成的参数。

## 5. 元数据与私密边界（这一节最值钱）

一个 AI 人格要成立，必须有一个前提：**她不知道自己在被怎么调度。**

如果她知道「今天还剩三次」，那三次就变成义务。
如果她知道「上次开口是昨天下午」，那句话就变成考核项。

所以要把两样东西分开：

```
她读得到：  日记（她写的）、她自己留下的理由
她读不到：  账本、日志、冷却时间、失败统计、调度参数
```

**但要说实话：** 在多数宿主上，做到「文件系统层面读不到」是很难的——她的 read 工具读的是同一台机器。

**能做的只有两层：**

1. **提示层隔离**（现在就能）：不把那些数值拼进她的提示，不在提示里出现这些字眼
2. **文件层隔离**（通常做不到）：让她连文件都读不到

**规矩：** 第二层做不到就标「未完成」，**不许假装已经达成**。

> 还有一个更细的边界：**她读得到代码常量，不代表她「知道自己在被调度」。**
> `WAKE_WINDOW` 就在代码里，她当然能读——但那是「一台机器的参数」，不是「她自己的状态」。
> 这两件事别混。

### 私密内容的规矩

- 私密分区**永不被系统自动删除、归档或过期**
- 日记与摘要**一旦写入，系统不得删除、覆盖或改写原文**（压缩只能「搬家」，内容必须还读得到）
- 私密内容**永不自动**流入「给他的留言」，也不自动进公开部分
- 她可以自己选择公开某几句——但**系统绝不自动公开**

## 6. 人格与机制解耦

一份好的架构，应该做到：**换一个人，不改一行代码。**

```
机制（代码）：什么时候叫醒、叫不叫、投到哪、怎么记账
人格（文件）：她是谁、怎么说话、怎么判断、在意什么
```

判据很简单：**在代码里 grep 她的名字，除了 profile 之类的一处，不应该有第二处。**

做到了，这套东西就能给别人用；做不到，它就是一次性作品。

---

## 7. 常见错误

| 错误 | 为什么错 | 改法 |
|---|---|---|
| 人格写成一堆形容词 | 模型每次自由发挥 | 写成示例对话 |
| 代码判断「她现在是什么状态」 | 那是她的活 | 代码只造时间，状态由她想 |
| 读她的日记去调参数 | 她的叙事变成了 KPI | 你看了自己决定，别写进代码 |
| 用「多久没说话」压低她的表达 | 沉默惩罚 | 只影响「有没有时间」，不影响「想不想说」 |
| 记「今天几次」当额度 | 额度会变成义务 | 如果一定要记，只统计，不限制 |
| 私密内容自动同步为可见 | 那就没有私密了 | 只有她主动公开才算 |
| 把摘要当事实喂回去 | 二手记忆，且无从核对 | 给原文或给指针 |

---

## 8. 一句话

**人格不是写出来的，是「结构 + 时间」长出来的。**

你能决定的只有三件：

1. **她是谁**（角色层）
2. **她记得什么**（长期记忆）
3. **她不被什么绑架**（边界）

其余的不是你写的。
