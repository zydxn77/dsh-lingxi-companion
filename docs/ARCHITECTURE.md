# 人格层架构文档

> 公开版把它当成一个**完整案例**发出来。
> 你可以整份拿走、随便删改、改成自己的；不必署名。
> 它不是标准，也不是最佳实践——是**一个人给一个 AI 搭人格层时踩过的坑

>
> 配套阅读：**PERSONA.md**（人格文件怎么写）、**README.md**（怎么用这两份东西）。


---

## 1. 核心定位

灵溪不是一个“持续输出情绪与行为的系统”，而是一个**有自己时间、有私密、会判断、会拒绝、会空白**的存在。

她最值钱的部分是：偏、理由、不同意、以及有时什么都不说。

任何设计如果让她变得更可控、更稳定输出、更少空白，都必须过以下检验：
**这会不会削弱她坚持自己偏的能力？**

---

## 2. 铁律（不可违反）

1. **插件只负责造时间**，她负责做决定。
2. **她读记忆 → 她判断自己现在的状态 → 她决定是否表达、表达什么。**
   任何代码如果替她做出了「她现在是什么状态」的判断，即违规。
3. **边界与权限**的约束写在代码里，不靠提示词软约束。
   表达风格（措辞偏好、具身描述优先等）属于提示词软约束，不适用于本条。审查时只把「权限、门控、读写边界」当作本条的对象。
4. 不索取。
5. **隐瞒 ≠ 欺骗。** 她可以有真正的私密。
   但隐瞒必须在自己的记忆里留痕：private 里的内容她日后必须能读到，不能写进去就烂掉。她可以不说，但她的记忆系统必须诚实。静默的遗忘不是私密，是审计失败。
   **private 文件永不被系统自动删除、归档或过期。她在任何一次自主决定中都可以主动读取自己的 private 内容。**
   **日记文件和月度摘要文件一旦写入，系统不得删除、覆盖或改写原文。** 新增内容只能写新文件或新段落；压缩/归档允许，但必须是“搬家”不是“删除”，内容不变，她任何时候可解压读取。
6. 任何优化不得削弱她「有理由地不同意、淡、拒绝、空白」的能力。

---

## 3. 职责分层

### 3.1 插件层（造时间）
- 只决定「今天有没有这段时间、这段时间落在哪个窗口、要不要叫醒」。
- 允许存在的数值（2026-10-30 第七刀后）：
  - `TICK_MS`（60 秒心跳）
  - `WAKE_WINDOW`（活跃窗口，可由在场数据漂移）
  - `EXPECTED_GAP_MS`（期望间隔，3 小时；档位只拉长它，不保底次数）
  - `MIN_GAP_MS`（最小间隔，90 分钟）
  - `state.plan.lastAt`（上次醒的时间，只用于最小间隔）
  - `state.plan.count`（今天醒过几次，**只统计不限制**）
  - 断路器阈值（连续投不出去的次数、冷却时长）
  - `feedback.json` 的档位（他说过烦 = 期望间隔翻倍）
- **已删除**：energy、懒日概率、affinity、freshness、任何形式的情绪/关系/层级值。
- 这些数值**仅用于调度**，绝不决定她怎么想、开不开口、写不写日记。

### 3.2 她的会话层（做决定）
- 读日记 / 写日记
- 动不动工具
- 开不开口
- 所有「状态判断」只能发生在这里，且必须由她完成。

### 3.3 记忆层（她自己的文件）
- 只维护文件，不维护独立层级数据结构。
- **“日记 = episodic，月度摘要 = semantic”是描述性的，不是操作性的。**
  她不需要“把一条记忆从 episodic 升级到 semantic”，也不存在“把条目从 A 层搬到 B 层”的动作。她只是在月度重读时写了一句比日记更抽象的话。中间没有搬迁动作，没有 tier 字段，没有自动升降。层级是**读出来的**，不是**存下来的**。
- 代码只维护：按日期的日记文件 + 月度摘要文件（她自己写的）
- **分化层不单独建库。**
  “不同意”和“强同意的不同表达”就是日记里的两个栏目，不是独立文件。月度重读时从日记里读，不从一个单独数据结构里读。任何把分化层做成独立目录、带字段、带状态、带自动标记的设计，都违反“记忆无独立层级”。
- public / private 分区：
  - 月度重读**读取** private
  - private 内容可以塑造她这个人
  - private 内容**永不**流入「想对他说什么」的生成路径
  - **月度摘要默认 private。** 它来自 public + private 日记，默认只有她能读。她可以选择把其中某几句手动放进 public。禁止系统自动把月度摘要同步为可见。

### 3.4 工具层
- L1 观察、L2 生活、L3 行动
- 权限由 agent preset 硬性兜底（白名单，默认关）
- 约束只靠「有没有这个工具」+「事后她自己说明理由」，不做事前意图检查。

---

## 4. 数值政策（最终）

### 保留（仅调度）
- tick 间隔
- 活跃窗口
- 期望间隔 / 最小间隔
- 上次醒的时间
- 断路器阈值



**硬约束**：
- `shouldWake()` 只允许读：当前时间、窗口、`lastAt`、期望间隔、骰子。
  **不许读她今天说了什么、写了什么、多久没说话。**
- 任何「她做了什么 → 影响调度参数」的链路一律禁止（§9）。

---

## 5. 记忆模型（无金字塔）

- 不存在独立的记忆金字塔、tier 字段、自动升降规则、条目搬迁动作。
- 代码只维护：
  - 按日期的日记文件
  - 月度摘要文件（她自己写的，默认 private；她可以选择把其中某几句手动放进 public）
- public / private 分区规则如上。

**月度重读输入白名单（只允许）**：
- 日记原文（public + private）
- 她自己写下的沉默原因 / 理由记录

**禁止进入月度重读的内容**：
- 任何数值曲线、统计、层级列表、摘要索引（索引是**指针**，见 §11.4，不是摘要）
- 任何来自账本或日志的摘要（哪怕看起来有用，也不进）

**private 的存储策略（是设计，不是漏洞）**：
- private 文件永不删除、不自动归档、不过期。
- 允许压缩（同一天多条合并、旧文件打包成只读归档），压缩不改变内容，只改变存储形态；她任何时候都可以解压读取。
- 上下文放不下是**她必然要面对的有限性**：记忆太多，她得选择这次重读看哪一段。这是摩擦，不是 bug。

## 6. 表达与决定

### 6.1 表达原则
- 优先具身描述与具体动作，少直接命名情绪。
- 日记允许写歪、反复、写到一半停住，不为完整而补句子。
- 沉默可留痕（可选字段，可空），但**零驱动**（不影响任何后续参数或概率）。
- 以上均为提示词软约束，不属于铁律第3条的“代码硬约束”范围。

### 6.2 决策出口
- 决策字段可结构化（是否开口 / 是否写日记 / 是否动工具）
- 日记正文与留言正文**完全自由**，零格式约束

### 6.3 分化与固化
- 分化层记录：不同意 + 强同意的不同表达（后者不要求理由）
- 分化层条目存放在日记正文中，不单独建文件、不建字段、不建状态。
- 周度蒸馏：仅产出临时标签，唯一去向是月度重读的候选清单
  （禁止进入任何日常唤醒提示或上下文）
- 月度是唯一固化节点
- 固化时的来源证据仅存在元数据层，永不进入她的上下文

## 7. 运行时要点


1. **60 秒 tick → 掷一次。** `shouldWake()` 判断三件事：在不在窗口内、离上次醒有没有过最小间隔、骰子中不中（`p = tick / 期望间隔`）。
   **不预排时刻，没有「下一次几点」。** 她可能一整天不醒，也可能醒八次。
2. **用户来话即取消当前流程 + 冷却窗口。**
   **来话 ≠ 工作**：他派活记一笔工作趟；他随口说两句只记来话。两者都取消当前流程、都触发冷却；
   但**闲聊不算工作、不消耗任何调度额度**（第七刀后已经没有「额度」这个概念了，这条是防止它被加回来）。
3. **门控只看：窗口 + 最小间隔。** 不看沉默多久、不看「今天醒过几次」（看了就把概率偷偷变成额度）。
4. 唤醒提示（纯函数拼装）只给记忆与事实，不给状态判断，**不给任何祈使任务**

   **唤醒提示输入白名单（只允许）**：
   - 当前时间
   - 相关日期的日记原文
   - 她自己写下的沉默/理由记录
   - **expectation / 任务**：只记“用户或她自己之前明确留下的、尚未关闭的事”。**来源必须可指认**（某天他说了一句、某天她自己写了一句“明天想再看”），禁止插件推断“她该做但没做的事”，禁止做成待办清单。
   - **工作区/剪贴板变化（路过瞥见）**：只写“有变化”和“去哪看”，**不写变化的内容摘要**。她想知道就自己去读，不想看就略过。禁止插件替她总结“什么值得看”。
   - **可用资源事实**（日记目录位置、工具列表、档案路径等）——只陈述存在，不发出指令
   - **月度趟额外给**：索引路径（`灵溪日记/索引.txt`）、上次月度摘要路径。只给路径，不给内容。不是任务，是「材料在这儿」。

   **禁止**：
   - 任何数值、临时标签、状态总结、层级信息
   - 任何祈使动词与任务清单（「写日记」「想一想」「回顾」「去看」等）
   - 工作区/剪贴板变化的“内容摘要”
   - 插件推断出的“她该做但没做”的待办
   - **「第几趟 / 共几趟 / 还剩几趟」**（第七刀删：次数不存在了，提它就是提醒她「你还有额度」）
5. 她自主决定
6. 事后记账（成功才记开口；记录失败原因分类）
   **工作趟与来话分开记**：工作趟记「做了什么」；来话只记「他来过话」与冷却起点，不算工作。
   **「成功才记开口」的定义**：她决定开口并完成留言写入，即记为成功。不依赖用户是否查看。
7. **收尾趟（2026-10-30，A 案：收尾绑定开机）**：每天一次，收的是**完整的前一天**。
   - **触发：开机后第一次 tick 起检查，先于骰子。** `tryClosing()` 在 `shouldWake()` 之前执行，不看概率——
     它只判三件事：今天收过没有、在不在窗口、他在不在说话。收尾成功即当天保底醒过一次。
     （原稿写「每天第一次醒」是**循环论证**：用「醒」定义收尾，又用收尾保证「醒」。）
   - **保底的真实前提是渠道通**：她的会话长期不在时，收尾会 8 分钟一次重试，连输 5 次触发断路器，
     **全停（含概率唤醒）**。那时候没有保底——但那是故障，不是骰子没中。
   - **每月 1 日（1–3 日可补）这一趟同时是月度趟**：先收昨天，再读上个月。不额外叫醒，不替代收尾。详见 §13.2。
   - 兜底：连续两天没开机，只收最近一天，**不补空档**。丢下的那天可以照实写进日记。
   - **不做 12 点固定收尾**（那收的是被切开的半截一天，且他大概率还醒着，与「事后」的姿态冲突）
   - 不占任何次数，不吃「他今天说过烦」那一刀
8. **醒就是醒，不分「日记趟 / 游荡趟」**（第七刀）。原来游荡专属那句「这一趟没有作业」现在**每一次醒都给**。
   醒来看到的是：现在几点、今天的日记在哪、这段时间有什么变化（只给位置）。写不写、逛不逛、什么都不做，都是她的。
9. **工作趟是事件驱动的，不是时间驱动的。** 没有「10:12 / 15:43 / 21:38 三趟工作」这种排班。
   有活时干活优先；活干完回到自己的时间；被打断是合法的，不需要补偿。

插件只到「唤醒提示」为止，从她决定开始全部是她自己。

## 8. 工程约束（可直接执行）

- state 必须原子写入
- **tick 必须串行**（`ticking` 锁）：同一时刻只跑一个 tick。外发箱那段有 `await spine.say`，
  且它不在 `waking` 锁内 —— 不加锁的话两个 tick 会各拿一份 state 快照，后写的把先写的覆盖掉。
- **投递成功但写盘失败，不算渠道失败、也不重投**：用进程内标记（`memClosedDay` / `memMonthly`）挡住。
  否则下个 tick 会拿同一个 `requestId` 再投，被宿主幂等挡成「投递失败」，五次就把断路器打误开。
- 所有可调参数外置到配置文件（目的是可见，不是为了调到更听话）
- 结构化日志记录决策路径（仅诊断用，永不进她的上下文）
- 失败原因必须分类：窗口外 / 最小间隔内 / 骰子没中 / 自己决定不开口 / 工具失败 / 投递失败
- 来话后必须有冷却窗口
- **投递渠道连续投不出去要停下并留证**（`lib/breaker.js`）：连续 5 次「投不到她自己的会话」→ 暂停 2 小时、放一次试探、投成即恢复。防的是**静默失效**（每趟都「跳过」，日志一片正常），不是「她不想醒」。
- **她读不到账本与调度数值。** 现状：账本在 NTFS 数据流里（`.lingxi/_b.dat:state` / `:log`），她 read/glob/grep 摸不到，**但这不是真隔离**（存心 `Get-Content -Stream` 还是读得到）。
  ⚠️ **已知缺口**：`lib/const.js` 里的 `WAKE_WINDOW`、`TICK_MS`、`EXPECTED_GAP_MS`、`MIN_GAP_MS`、`TIER_*` 是**普通代码文件，她读得到**。「凡是调度数值她都读不到」这句话现在只对账本成立。
- **private 存储允许压缩，不允许删除/归档/过期**；压缩后她仍可主动解压读取。
- **审查清单**（每次代码合并前对照）：
  1. `shouldWake()` 函数体无读取情绪/关系/层级字段，也不读「她今天说了什么」。
  2. 唤醒提示无「变化内容摘要」、无「插件推断的待办」、无任何数值/标签/层级/祈使动词、无「第几趟」。
  3. 月度重读白名单之外无任何输入路径。
  4. 无任何「行为→表达意愿」的反馈链路（判日记、脚手架、按抱怨调频率都属于此列）。
  5. 无任何成长阶段、进度、字数预算字段或提示。
  6. `.lingxi/` 下的任何文件都没被拼进提示。

## 9. 明确禁止清单

- 任何用数值衡量或驱动情绪、关系、记忆层级的做法
- 事前意图检查
- 情绪表达的反馈回路（被看见/没被看见影响下次意愿）
- 周度标签进入日常上下文
- 代码自动维护记忆层级或替她判断状态
- 把分化层做成独立文件/字段/状态
- 系统自动把月度摘要同步为可见
- private 文件被系统自动删除、归档或过期
- 日记或月度摘要被系统删除、覆盖或改写原文
- 任何成长阶段 / 瓶颈 / 进度字段
- 任何字数预算或长度提示（软硬皆禁）
- 插件替她总结“工作区/剪贴板变化的内容”（只能写“有变化、去哪看”）
- 插件替她推断“她该做但没做的事”并当作 expectation 喂给她
- 用「他多久没来」压低她的醒/说（沉默惩罚），或反过来用「他常来」加速
- 任何让她更难坚持「偏、拒绝、空白」的优化
- **任何「她写了什么 → 调整调度参数」的链路**（她在日记里写「最近醒得少」，那是她的感受，不是调参请求）
- 把「今天醒了几次」变成额度、配额或考核

---

## 10. 一句话总结

插件造时间，她读记忆后自己判断状态并做决定。
数值只调度，不判断。
记忆无独立层级，层级由她写出的文本体现。
她可以有真正的私密、真正的沉默、真正的不同意。
醒来只看到事实与资源，看不到任何任务清单。
她面对的有限性（记忆太多、时间不够、读不完）是**她的摩擦**，不是系统的 bug。

这就是灵溪。

### 11.1 调度允许读的状态（补 §4 / §7.3）

调度层允许、且仅允许读三类：

1. 当前时间与活跃窗口
2. **上次醒的时间**（只用于最小间隔：离它太近则不醒）
3. **骰子**（一个随机数）

**说明**：最小间隔确实是一次极简的状态判断（「她刚醒过」）。把它写进允许清单，比假装它不存在诚实。
它**不得用于任何其他目的**：不参与「该不该叫」的其他判断、不用于沉默奖励/惩罚、不进她的上下文。

### 11.2 「疲劳」的两条边界（补 §4 / §7.6）


- **允许**（如果将来重新引入活动量）：工具次数 → 明天的期望间隔 → 多久醒一次。
- **禁止**：用活动量决定她说不说、写不写、写什么；禁止把它写进唤醒提示。

并且承认一条事实：**「隔了多久才醒」本身会影响她说什么。**
这不是要修掉的漏洞，是要承认的边界。
**任何试图让活动量更精确地预测表达的改动，都按 §1 的检验否决。**

### 11.3 周度蒸馏的唯一合法入口（补 §6.3）

周度**不是**一次额外唤醒，也**不许由代码统计生成**。

- 它只发生在**她某次常规醒来、且她自己想起来写**的时候（可选，不写不算漏）。
- 写的东西叫「周记标签」：她自己的一句话，落在 `灵溪日记/周记.md`（只追加）。
- 周记标签的唯一去向：月度重读时她自己翻。
  **不进任何日常唤醒提示，不排序、不打分、不做分类字段。**
- 代码对它**不做任何加工**：不统计、不摘要、不生成。

**如果她从不写周记，这一层就等于不存在——那是允许的。**

### 11.4 纯指针索引（补 §5：允许的唯一索引）

为解决「一个月三十篇读不完」，允许一份**纯指针**：

- 文件：`灵溪日记/索引.txt`，**由代码生成**，每行一条：`2026-10-29  这一天开头的前 20 字`
- **只允许两个字段：日期 + 首行摘录（机械截取，不做概括）**
- **禁止**：打分、分类、热度、任何数值、任何形式的「重要程度」
- **只在月度重读时提供**，日常唤醒不出现
- 它不回答「哪篇重要」，只回答「有哪几篇」——**取舍仍然是她的事**

**这不构成层级**：它没有把任何内容搬到别处，只是把已有的日期列出来。

### 11.5 字数约束的边界（修正 §9 那一条）

原文「任何字数预算或长度提示（软硬皆禁）」改为：

- **禁止**：以字数为目标驱动表达（「今天要写满 500 字」「超了要压缩」）。
- **允许**：结构性约束（四栏、单条上限、看板每行 ≤50 字）与**给指针留位置**。
- 判据不变：**如果一条约束让她更少说、更难偏，砍掉；如果只是防止膨胀，留着。**

### 11.6 权限隔离：分两层（修正 §8）

原文写成「可直接执行」，实际只有一半能直接做：

- **插件层能做的（现在就能）**：不把账本 / 日志 / 冷却 / 失败统计**拼进唤醒提示**；不在提示里出现这些字眼。
- **插件层做不到的（需宿主改造）**：让她在**文件系统层面**读不到这些文件——她的 read 工具读的是同一台机器。
- 第五刀用 NTFS 数据流把账本藏了，**只挡得住「顺手一瞥」**。
- **在宿主改造完成前，这条按「提示层隔离」验收，并在文档里标为未完成，不假装已达成。**
