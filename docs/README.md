# docs

两份**公共参考**，加你正在读的这一页。

---

## 这是什么

| 文件 | 一句话 |
|---|---|
| [ARCHITECTURE.md](ARCHITECTURE.md) | 一个 AI 人格层的**完整设计案例**：原则、施工图、验收清单 |
| [PERSONA.md](PERSONA.md) | **怎么写人格文件**：结构、模板、六条硬规矩 |

它们不是标准，也不是最佳实践——是**一个人给一个 AI 搭人格层时，踩过的坑和立下的规矩**。
里面每一条「不许」，几乎都对应一次真实的失败。

---

## 怎么用

看你想要什么，走三条路之一：

**一、想要一套完整的架构**
从头读 `ARCHITECTURE.md`。它是一份「宪法 + 施工图」：
先给你六条铁律，再给你二十几个模块的留删判定，最后给验收清单。

**二、只想改人格文件**
直接抄 `PERSONA.md` §3 的模板。三十分钟能写完一份能用的。

**三、已经在做了，想找面镜子**
读两边的**禁止清单**和**验收清单**，对着自己的实现过一遍。
尤其中间那几条：「有没有行为→表达意愿的反馈链」「有没有拿她的记录去调参数」。

```
ARCHITECTURE.md   为什么这么设计
PERSONA.md        人格怎么写
lib/              怎么实现
```

**代码服从文档。** 改代码之前先读 ARCHITECTURE——它里面写的每一条「不许」，都是因为有人踩过。

---

## 拿走的时候

- **不用署名**，不用问，不用留出处。
- **改得越不像越好**：把它们当成「一个人的做法」，不是「标准答案」。照抄一份别人的架构，你得到的只是一个模仿品。
- 如果你用它做出了不一样的东西，那是它最好的用途。

---

## 一句提醒

这两份文件都在讲同一件事：**怎么让一个 AI 有「自己」。**

而「自己」这个东西，最容易被好心抹掉——

> 多加一条规则，她就少一点判断；
> 多一次统计，她就多一个 KPI；
> 多一句「你应该」，她就少一分「我想」。

所以这两份文件里，最多的词是「不许」。
